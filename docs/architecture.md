# Architecture

## Runtime and entry points

Penjat is a React 19/Vite 8 TypeScript SPA and a Node HTTP service with Socket.IO 4. There is no Express, router library, database, global state library or runtime vocabulary API. `src/main.tsx` mounts `App` in StrictMode. `src/routing.ts` normalizes paths; `App.tsx` manages browser history, modes, interface/game language, room snapshots, chat, the site header/footer and guarded exits. Routes: `/`, `/multijugador/`, `/aprendre/`, `/paraula-del-dia/`, `/com-es-juga/`.

`server/server.ts` serves `dist/`, route-specific SEO metadata, legacy Spanish redirects, `/health`, room previews at `/api/rooms/:code/preview`, and Socket.IO. Development uses Vite plus the separate server; production serves both on one origin. There is no service worker or backend persistence. `render.yaml`, README and package scripts describe single-process hosting; deployment is outside routine verification.

```mermaid
flowchart LR
  App[App / pages] --> Learning[Learning and daily rules]
  Learning --> Data[Bundled vocabulary JSON]
  App <-->|typed Socket.IO events| HTTP[server/server.ts]
  HTTP --> Manager[GameManager: identity and room registry]
  Manager --> Room[GameRoom: authoritative match state]
  Room --> Views[Recipient-specific PlayerGameView]
  Views --> App
  Shared[shared game rules / protocol] --- Room
  Shared --- Learning
```

## Ownership and boundaries

| State | Owner | Lifetime |
| --- | --- | --- |
| Learning round, attempt history, summary | `LearningPage`, pure `learning/game.ts` rules | Mounted page only |
| Daily round | `DailyChallengePage`, `daily/game.ts` | Replayed from local storage for current Madrid date |
| Homepage daily summary (number, won/lost, mistakes) | `HomePage`, pure `daily/homeSummary.ts` | Re-read on mount, focus, storage events and each minute; never shows the word |
| Match, score, turn roster, forgiveness, secret word | `GameRoom` | Server process / room |
| Identity → room/socket mappings | `GameManager` | Server process |
| Absence and empty-room timers | `GameManager` (injectable scheduler) | Away 2 min after socket loss, or at once when a permitted player continues without a blocking one (seat kept); room deleted 30 min after nobody is connected |
| Room view, chat display, typing display | `App` | Current client |
| Name, languages, learning progress (`penjat-learning`) | `localStorage` | Browser origin |
| Room code/player ID/reconnect token | `localStorage` (`hangman-room-session`, version 1; legacy unversioned sessionStorage entries are migrated) | Browser profile: survives refresh, closing and reopening the tab, and mobile tab discards; shared by tabs of one profile |

Clients send intent (`game:guess`, `round:set-word`, etc.). Server resolves socket identity, validates, mutates `GameRoom`, acknowledges and broadcasts individually serialized `viewFor(playerId)` snapshots. Guessers never receive the active secret word or other players' private progress; setter observation receives a selected board and setter-only forgiveness requests. Chat uses separate events and a bounded in-memory history of 50 messages. Completion retains the room for rematches. Only explicit departure removes membership (the last one deletes the room); after the reconnect grace a disconnected player is away, keeping the seat while the game moves on, and a room with nobody connected expires after the empty-room TTL.

## Vocabulary and local game logic

`learning/units.ts` validates the curated `data/learning-units.json` (six units of exactly 12 words; only `ready` units are shown in production) and `learning/progress.ts` holds the saved progress and per-unit sessions (see [gameplay contracts](gameplay-contracts.md)); `learning/game.ts` has the round rules. Word illustrations are SVG files in `public/learning/words/`, unit emblems in `public/learning/units/`. `learning/vocabulary.ts` validates the bundled 544-entry `data/vocabulary.json` corpus, whose CEFR metadata is kept but not used by learning. Daily mode resolves a fixed 32-ID ordered pool against the same dataset; day index from the Madrid date and fixed epoch selects the word.

The offline Python pipeline is in `scripts/vocab_pipeline.py`, with small command wrappers. Source/license and review provenance live in `data/README.md`; approved baseline is `docs/vocabulary-v1.md`. Experiments under `data/experiments/` are ignored and must not become runtime dependencies. Reviewed metadata is merged by stable ID using `data/review/linguistic-metadata.json`. Ordinary builds never call external APIs.

`shared/game.ts` is the active shared normalization/matching implementation. Older `src/game/game.ts` and word lists remain; inspect callers before reusing them. Learning and daily rules are similar but have different session/persistence lifecycles.

## Styling and typography

Plain CSS: `src/index.css` holds the font faces and shared tokens, and `src/App.css` holds component rules. There is no CSS framework.

- **Fonts.** `--font-display` (self-hosted Fraunces, with Georgia/serif fallbacks) is for the brand, expressive headings, game words and outcomes. `--font-ui` is for body text, controls, names, chat, scores and functional panel titles. It is *Penjat UI*, a self-hosted 30.6 kB WOFF2 subset of Source Sans 3 (OFL, renamed because of the Reserved Font Name; see `src/assets/fonts/README.md`), with metric-matched Arial/Helvetica fallback faces in regular and bold (with `font-synthesis: none`, a regular-only fallback would flatten all semibold/bold text if the web font fails). The build preloads the hashed font (`vite.config.ts`).
- **Identity.** The exact Lovable OKLCH paper/ink/magrana/saffron/teal/olive palette and contrast-tested semantic roles (including `--mar-surface`/`--oliva-surface` tints) live in `index.css`. Buttons and major cards use Lovable's printed treatment: 2px ink outlines and 3px (phones) / 4px offset shadows that lift on hover and press in on click (no movement with reduced motion). Segmented choices and the selected option are inked; supporting panels (help sections, history rows) keep outlines without shadows. Display headings use `--text-hero`/`--text-display`/`--text-section`/`--text-card-title` and an italic accent word (`<em>`, slant synthesised only there because Fraunces ships one upright face). Labels are sentence case, not small uppercase. The shared `HangmanDrawing` has explicit six-error body parts, hat/head and scarf/torso pairs, a rescued victory pose and a quiet defeat expression. Adjacent translated counts/outcomes make game/result drawings decorative. Only newly revealed parts animate, with reduced-motion support.
- **Site shell.** `SiteHeader` replaces the old floating back button and language toggle: wordmark link, the four routed sections (`navigation/links.ts`, `aria-current` on the current one, which alone gets a compact ink pill like the selected CA/ES code; the header is a compact 56px bar on a hairline: 14px links in 32px pills, a 28px badge, an 82×34 CA/ES pill and 36px round controls, each keeping a 44px hit area), a contextual exit (`.global-back-button`: leave the room/match, end the learning session) and the CA/ES pill. From 1000px the sections are inline; below, a disclosure button opens an overlay menu (no layout shift) with Inici and the sections; it offers the interface language only where the header hides its CA/ES pill (below 384px beside a contextual exit, and below 320 CSS px), so the language appears once. It closes on Escape (focus returns to the button), an outside pointer press, focus leaving the header, navigation, and growing past 1000px. Below 384px a contextual exit replaces the header language pill (still in the menu). The header scrolls with the page; it is sticky only on large content pages (home, help, multiplayer setup ≥1000×600). `App.navigate` guards header links: leaving a waiting room or an active match, or an unfinished learning/daily game, asks first (`ExitConfirmationDialog` has `game` and `room` copy). Browser Back/Forward use the same guard (`navigation/history.ts`): every entry the app writes stores `penjatIndex`, so a guarded popstate is undone with `history.go(-delta)` and the dialog opens on the page it protects; Cancel keeps the game, Confirm replays the move. Any applied history move closes a pending dialog and leaves a room (as header links do). A skip link focuses `<main>`. `SiteFooter` (a light strip under a hairline: wordmark, tagline and the section links) closes the home, help and setup pages. On the homepage a static, decorative (`aria-hidden`) full-bleed ink band of Catalan words with saffron ✦ separators divides the hero from the mode cards; the words drift left at an ambient 6 CSS px/s (`BAND_SPEED` in `HomePage`): `WordBand` renders identical copies, each a whole number of pixels wide, and shifts by exactly one copy per linear cycle, so the loop is seamless; it measures the band and renders `ceil(bandWidth / copyWidth) + 1` copies so the moving track covers any viewport or zoom. The band itself is the pause control (a native button with a CA/ES pause/resume label and tooltip; click, tap, Enter or Space; inset saffron focus ring) while its words stay hidden from assistive technology; with reduced motion it renders as a static, non-interactive band. The band has more room above than below, and extra space before the mode section. From 600px the hero's daily entry is a tertiary one-line hairline pill (no fill or shadow) under the two actions. The mode cards lead with their title (no icon badge), and the main hero action carries a CSS-drawn arrow so its accessible name is unchanged. Page heads (`.page-head`: colour eyebrow, Fraunces heading, lede) replace the per-page brand marks.
- **Phone homepage hero.** At ≤599px (37.4375em, so enlarged text also gets it) the hero is a single column: eyebrow, `<h1>` and lede, then the character drawing and letter slots without the preview card frame, then `.home-quick`. That nav repeats the `.home-modes` destinations in a new order: a full-width ~104px magrana **Jugar** link (`/multijugador`, the existing main action; there is no separate solo mode) and two equal 68px cards, *Aprèn vocabulari* and *Paraula del dia*, with the challenge number and a ✓ once played. Phones hide `.home-modes`, and wider screens hide `.home-quick`, so only one of the two is ever rendered or focusable. The tablet and desktop hero are unchanged. Below 480px the card icons lose their circles and the labels step down. Below 360px the drawing shrinks and the Jugar arrow is hidden. Below 320 CSS px the cards stack and Jugar centres its content.
- **Lobby rules.** Below the code and invite actions, the "Regles de la partida" box (`.invitation-rules.lobby-rules`): a heading row and the current settings as two pills ("En català · 3 rondes"), live for everyone (`aria-live`). Only the current host sees "Configura" beside the heading; it opens a native modal dialog (`Modal`, the exit dialog's frame) with the existing game-language and rounds selectors, a note that changes apply immediately for everyone, and "Fet". Each choice is sent at once and confirmed by the server (controls disabled while pending, errors shown in the dialog); Escape or "Fet" closes it and returns focus to "Configura". If the host role moves to someone else, the dialog closes and does not reopen. Non-hosts see "Esperant que {host} comenci la partida". The meta line keeps only the player count.
- **Multiplayer entry.** One inked card on the warm `--surface` (`.setup`, 34rem wide like the page head) at every width: a single name field (pre-filled with the remembered name), the red primary "Crea una sala" action with a one-line muted hint (rules are chosen in the room), then "Uneix-te a una sala" as an ink-outlined secondary action on `--paper`. Opening it replaces that button in place, above a hairline, with the room code and an "Entra" button of the same secondary weight on one row, keeps the name and focuses the code. Two sibling forms, so Enter in the name creates and Enter in the code joins. Both need the shared name, and joining a five-character code; missing values are explained in the panel (and focus moves to the field) instead of disabled buttons. Invitation links keep their own card.
- **Lobby and chat.** The copy action is an inked pill hanging off the room-code slab; a refused clipboard shows a CA/ES alert under it. From 1000px, chat remains a sidebar panel. Below that boundary, a persistent bottom rail opens the same transcript/composer in a full-screen native modal dialog, with explicit close, Escape, focus/scroll restoration, safe-area padding and visual-viewport sizing for the keyboard. Header/composer do not shrink; the transcript takes the remaining space. The mobile root allocates space for the rail outside the scrolling game viewport, including below result actions. App owns the draft/open state across lobby/game transitions. Consecutive messages from one player within two minutes share name/time metadata. A 32px reaction trigger stays inside the bubble without extending its hit area into adjacent rows; its floating picker has 44px emoji buttons and is portaled directly into the chat dialog, outside transcript clipping/scrolling ancestors. Reaction summaries reopen that picker. Picker dismissal checks both trigger and portal event paths; scroll/viewport events reposition instead of closing it. Only keyboard activation moves focus into the picker. Reactions emit once from native click.
- **Chat awareness.** `multiplayer/chatInbox.ts` separates initial history, live arrivals and reconnect catch-up, deduplicates by message ID, and retains a bounded room/player-scoped known/unread snapshot in session storage through `useChatInbox`. Initial history is silent; subsequent history adds missed unread messages without preview/sound. No overlap with a full history uses a general unread indicator instead of claiming an exact count. A read requires a visible document, no other blocking modal, following the list end, and the latest bubble actually visible. Incoming messages never move a reader of older messages; a jump control returns to the latest. Unread badges remain until that read condition. One five-second preview coalesces a burst rather than extending indefinitely. Optional sound is off by default, gesture-activated with a confirmation cue, muted while reading/hidden and limited to once per eight seconds; blocked activation/playback reports a localized error and never queues delayed playback. Read measurements do not consume the separate live notification event. Reactions and typing never notify. The existing server protocol, identity and lifecycle remain unchanged.
- **Type scale.** Semantic rem tokens (`--text-body`, `-control`, `-name`, `-chat`, `-meta`, `-label`, `-panel-title`, `-page-title`, `-outcome`, `-score`, `-lede`) take phone values, then step up at 661px (body 17px, labels 14px) and 1200px (body 18px, metadata 16px, labels 15px, panel titles 26px, page titles 34px); navigation stays a compact 14px. Use the tokens rather than literal sizes. The root font size stays at the browser default, so user text settings apply.
- **Breakpoints** are written in em (px ÷ 16), so a larger default text size switches to the narrower layouts. Sidebar and column widths are capped with viewport-relative `min()` so enlarged text never squeezes the board.
- **Gameplay shell.** Three columns (ranking · board · forgiveness/chat) from 1300px. From 1000–1299px the board stays wide, with ranking and chat in a 18.5rem sidebar. At 999px and below the forgiveness tray, board and ranking stack; chat uses the persistent rail and modal sheet described above. The ranking follows the board in the DOM at every width; beside the board the grid area places it in its own column. Grid rows have no row gap, so an absent forgiveness tray never offsets the other cards. An empty chat (`.room-chat.is-empty`) is a compact card rather than a full-height column. Room facts are one unframed line (muted labels, ink values; right of the title from 661px). Live and final scores use the UI face with tabular figures; panel titles, including the final standings, use the display face. From 661px the two-column board gives the guess column the width: word tiles up to 48px with display-face glyphs up to 38px, and a 7-column keyboard of 48×48px keys (capped below the 9-column threshold). On phones (≤660px) the board is a single grid: the drawing column and guess column wrappers use `display: contents`, so the drawing sits beside its error count and wrong letters, followed directly by the word and keyboard (DOM, reading and focus order unchanged). A returning player shows as a quiet `.reconnected-notice` strip; `.connection-notice` stays reserved for a player who is reconnecting.
- **Compact live ranking.** `Scoreboard` (helper `src/multiplayer/liveRanking.ts`) renders the full list plus, from four participants, a summary (leaders by name up to two, otherwise a tie count; the player's own place, marked as tied when shared) and a native disclosure button (`aria-expanded`/`aria-controls`). CSS shows the summary and button only in the stacked layout; beside the board the full list is always visible. The expanded state is component state, so live `room:state` updates never collapse it. The final match classification is unaffected.
- **Match results.** The outcome is a full-bleed band at the top of the results card, coloured by `outcome-*` kind (saffron for a win, the sea tint for a shared first place, paper otherwise), with the shared `HangmanDrawing` on a small rotated inked card (rescued pose for a win or shared first place, quiet defeat otherwise; decorative, the only drawing on the match-over page). The card settles in once on mount (no motion with reduced motion). Every first place, including tied leaders, wears an inked saffron rank disc. From 1000px the results column is capped at 46rem beside the chat, centred with the header; on phones the lede spans the band under the art and the fixed action bar sits above the reserved chat rail.
- **Completed words.** Learning and daily results share one presentation: a small drawing beside the outcome and the mistake count, the Catalan word once as a Fraunces heading (focused with `tabIndex=-1` when the round ends in this visit), then definition/example or definition/translation. The tiles and the drawing column are not rendered after completion. From 900px the learning card uses two columns so “next word” stays near the top.
- **Letter keyboard and touch targets.** The shared `Keyboard` is a size container with balanced rows at every width: 7 columns (CA 7/7/7/5, ES 7/7/7/6), or 9 (9/9/8, 9/9/9) once a 24.375rem keyboard fits a 38px key. Keys are 44px tall and fill the row up to a cap below the next column count, so the row layout never changes with a stray extra key. The CA/ES pill keeps its visual size and gets an invisible, vertical-only 44px hit area (`::before`). Chat uses contained 32px bubble actions and 44px picker buttons, with no expanded hit areas crossing message boundaries.
- No global `min-width`: below 320 CSS px (zoomed phones) pages keep reflowing. Only word strips scroll horizontally.

## Persistence and limits

Daily storage (`penjat-daily-challenge`) stores one date's guesses/result; restore (including the homepage summary) reconstructs the round from guesses, not trusted score flags. Learning progress (`penjat-learning`) keeps the latest result per word, bookmarks and one session per unit; the open unit survives a refresh through session storage (`penjat-learning-unit`). Interface preference is separate from `hangman-game-language`; multiplayer name uses `hangman-name`. Room credentials use `hangman-room-session` in local storage (`multiplayer/roomSession.ts`): malformed or other-version entries are ignored and there is no client-side expiry; `createRoomRestorer` owns restoration (one resume per connection, late replies ignored, retry, explicit leave that clears only credentials this tab holds). The entry screen re-reads the stored session on submit (`entryDecision`): the same room resumes, another room or a new one asks before `abandonRoomSession` gives the seat up. While restoring, `App` shows `RoomRestoreNotice` instead of a page, or the own-connection strip over a room still on screen. No accounts or cross-device saves exist. Restarting the server loses all rooms; multiple replicas cannot share state.

## Incremental concerns

- `App` combines routing, socket subscriptions, restoration and metadata. Extract a small session coordinator only when further lifecycle work requires it; keep recipient views as the UI boundary.
- `GameRoom` combines game state and chat; avoid large refactors until contracts cover the proposed separation.
- Offline artifacts and runtime metadata can drift. Add coverage checks before considering pipeline restructuring; do not blindly rebuild approved lexical data from older inputs.
- UI metadata and HTTP SEO metadata are duplicated; a shared route table is a future focused cleanup.
- Each page has one URL for both interface languages. The served HTML (what crawlers get first) carries the Catalan title, description and canonical; Spanish metadata is applied in the browser only, so there are no `hreflang` alternates. Indexing Spanish separately would need crawlable language URLs (the legacy `/es/…` paths currently 308-redirect to the Catalan ones). The learning unit names render with JavaScript; the `/aprendre/` description names the themes for crawlers that do not render.
- Existing Socket.IO E2E tests exercise independent clients, not browsers, storage or navigation. See development docs for test isolation.
- The eager vocabulary import contributes to the existing >500 kB bundle warning; route-level code splitting is optional follow-up.

## Product decisions

- There is no generic solo mode: the homepage **Jugar** goes to multiplayer; learning and daily are the single-player modes. `src/game/game.ts` is an unused first-commit helper, not a mode.
- Catalan copy never puts a personal article before a display name ("Júlia ha guanyat") and avoids gendered adjectives about players: gender cannot be inferred from a name.
- Match results never claim "ended early": the snapshot has no completion-reason field, and `completedTurns` counts cancelled turns.
- Deliberately not adopted from the Lovable prototype: invented activity numbers, streaks, timers or percentiles, a word ticker, a podium (it hides shared ranks) and a horizontal ranking strip.
- The learning mode is "Aprèn vocabulari" in Catalan and "Aprende vocabulario" in Spanish; its URL stays `/aprendre/`.

## Known limitations

- Daily mode rolls over on remount, not at a guaranteed midnight refresh.
- A one-player finished room can request a rematch but cannot start one; room capacity, absence grace and empty-room TTL are constants; away seats count toward room capacity; active matches admit no late joins or spectators.
- On phones the match meta pills wrap to two rows; the "Torn n/m" pill shows completed turns.
- Fraunces has no metric-matched fallback; its italic accent is synthesised (a real italic subset would cost ~55 kB).
- Browser coverage is mainly headless Firefox with resized viewports (Chromium/WebKit were exercised once through `scripts/browser-driver.mjs`); no physical iOS/Android device or screen-reader session has been run.
